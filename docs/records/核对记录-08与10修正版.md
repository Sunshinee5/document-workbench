## 二、08 章引入的新架构变更（必须同步，否则返工）

### 变更内容

08 章第十节定义：

- ExecutionContext 是**一次 Task 执行上下文**，不是 Session 成员。
- 生命周期：Task 创建 → Context 创建 → Task 执行 → Task 结束 → Context 释放。
- 内容是各对象的 **Reference**（Session Reference / Document Reference / Workspace Reference），不是按值持有。
- 10 修正版第十二节与此一致。

### 与现有文档/骨架冲突

| 位置 | 现有定义 | 08/10V1.1 定义 | 冲突 |
|------|----------|----------------|------|
| 09 章第六条 | ExecutionContext 属于 Session | 不是 Session 成员 | 归属相反 |
| 骨架 `context.rs` | 8 字段全按值持有（session: Session, document: Document, workspace: Workspace...） | 持有 Reference | 持有方式相反 |
| 骨架 `context.rs:2` 注释 | "Session 逻辑归属于此，以单向持有避免递归" | — | 注释与新定义矛盾 |
| 00-B V1.1 第九条 | ExecutionContext 字段：Session/Document/Workspace/Selection/CapabilitySet/Config | 08 章：Session Ref/Document Ref/Workspace Ref/CapabilitySet/Config/Progress/CancelToken | 字段表述不一致 |

### 影响判断

这不是文档笔误，是一次实质架构调整：ExecutionContext 从"全局共享的会话级上下文"变成"每次 Task 执行的临时上下文（引用语义）"。

**好处**：彻底解决困扰多轮的执行上下文归属矛盾和 Rust 按值持有循环引用问题。这与 09 章"Session 只存状态"、10 章"Workspace 被动状态容器"的哲学一致。

**代价**：09 章第六条、骨架 context.rs、V1.1 第九条字段表都需要同步修改，否则 Agent 会读到三套互相矛盾的 ExecutionContext 定义。

### 建议（需用户拍板）

1. 确认采纳 08 章的 ExecutionContext 新定义（推荐：采纳，它解决了循环依赖）。
2. 同步修改：09 章第六条、00-B V1.1 第九条字段表、骨架 context.rs（改为 Reference/生命周期语义）。
3. 重跑骨架测试（GNU target）确认无回归。
