## 用户四项最终架构裁决

| # | 裁决 | 落地 |
|---|---|---|
| AD-25 | Save 唯一消费 ContentPatch | `PdfSaver::stage_content_patch()`；Save 不调 ObjectMapper、不生成 Operator |
| AD-26 | RoundTrip 冻结 | IT-07 / IT-08 覆盖重新 Parse 后对象一致 |
| AD-27 | Patch 生命周期冻结 | Patch 不进 History / Snapshot / 持久化；Save 取走暂存即释放（IT-09） |
| AD-28 | Save 不重新计算字体 | Save 只序列化已有 `PdfOperator`，无 Glyph Resolve / Subset |

## 主理人冲突裁决

| # | 冲突 | 裁决 |
|---|---|---|
| C-1 | AD 编号一致 | 无冲突 |
| C-2 | AD-25「Save 禁调 ObjectMapper」vs 18-01「Object → lopdf 反向同理经 Mapper」 | Mapper 保留为**对象 ↔ Intermediate 数据映射**（Parse / MT-04 仍用），**不参与 PDF 写回**；18-01「Object 永不直改 PDF」铁律不变——经 ContentPatch 间接写回 |
| C-3 | AD-26「RoundTrip 保持 Object 一致」vs 写回新字形导致重新 Parse 后 `glyphs` 变化 | **跨 Parse 判据**：ObjectId / BBox / kind / z_index（IT-07 实测稳定）；**内存侧判据**：version / lifecycle / unicode（Save 前后不改 Object Tree）；`glyphs` 由 Parser 从新流重新派生，预期变化 |
| C-4 | AD-27「Patch 不持久化」vs IT-04「Undo Redo Save」 | Undo 用 `Diff::revert_object()`，不用 Patch；Undo 后再 Save 必须重走 18-06→18-08 生成新 Patch |
| C-5 | §三「禁止新增编辑能力」vs AD-25 要 Save 消费 Patch | Save 侧**写盘适配**不是编辑能力；只加 `stage_content_patch()` 应用已有 Patch |
| C-6 | IT-06 要求内容流改动进增量包，但既有 `write_incremental()` 只搬运布局对象与 root | `stage_content_patch()` 把内容流 xref 记入 `StagedChanges.content_object_ids`，`write_incremental()` 并入 `changed` |
| C-7 | Save「禁止重新生成 Operator」vs 把 Patch 编码进流字节 | 只调 `encode_operators()` 序列化已有 Operator，不新建、不改名字/操作数 |
| C-8 | IT-10 Memory Leak 无可测判据 | 判据：100 轮后页面对象数、Operator 数稳定，Save 取走暂存后 Patch 不可再消费 |
| C-9 | §八「Regression 覆盖 18-01~18-08 全部」但部分章节无写盘语义 | 分层：Rust 层跑全部既有 dw-core/dw-pdf 测试（189 条），端到端层跑 IT-01~10；合并才算覆盖 |

## 补充裁决

- `stage_content_patch()` 必须先调用 `apply_changes()` 暂存，否则报中文错误；Save 取走暂存后再次 stage 同样报错——从 API 上落实 AD-27 的「一次性」。
- `/Contents` 支持单个 Reference 与 Reference 数组；数组按 `patch.stream_ref` 精确匹配，找不到即报错，不猜测。
- `resolve_layout_objects()` 的页码基准是 **1 起**（lopdf `get_pages()` 也为 1 起），集成测试踩过后已固定。
- 增量保存可用性与 `Document.metadata.file_size` 绑定：测试构造 Document 时必须回填文件大小，否则被判为外部改写而回退全量。
