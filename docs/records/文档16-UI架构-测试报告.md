## 四、`dw-desktop` 编译阻塞说明（环境问题）

本机尝试 `cargo check -p dw-desktop` 时，依赖链在 `parking_lot_core 0.9.12 → windows-link` 处失败：

```
error: error calling dlltool 'dlltool.exe': program not found
```

原因链（与 `05` §7 记录的历史问题同源）：

1. `windows-link` 在 `x86_64-pc-windows-gnu` 目标下用 `#[link(kind = "raw-dylib")]`，
   需要 rustc 调 `dlltool` 生成导入库；
2. 本机 rustup 自带的 `dlltool.exe` 可用，但它内部还要调用汇编器 `as.exe`；
3. 本机**没有** `as.exe`（无 MSVC、无完整 mingw-w64 binutils），`dlltool` 报 `CreateProcess` 失败。

因此：**`dw-desktop` 在本机无法编译**，与本次代码无关。已验证：
- 把 `parking_lot` 降到 0.12.4 + `parking_lot_core` 0.9.11 后，下一个 `windows-sys 0.61` 仍在同一处失败，
  说明这不是单点依赖问题，而是缺工具链；
- `Cargo.lock` 已还原，**未把降级带进仓库**；
- `ipc.rs` 的语法与格式由 `rustfmt --check` 验证通过，对象树投影逻辑本身在 `dw-pdf` 内编译 + 测试通过。

**后续建议**：给构建机装一份完整 mingw-w64 binutils（提供 `as.exe`），或改用带 MSVC 的构建机，
再执行 `tools/verify.ps1` 的 Tauri 构建环节。这一项属于环境待办，不影响 UI 与核心层交付。
