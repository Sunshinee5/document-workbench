## 四、`dw-desktop` 编译与打包（阻塞已解除）

### 4.1 原阻塞

首轮验证时 `cargo check -p dw-desktop` 在 `parking_lot_core 0.9.12 → windows-link` 处失败：

```
error: error calling dlltool 'dlltool.exe': program not found
```

原因：`windows-link` / `windows-sys 0.61` 在 `x86_64-pc-windows-gnu` 下用 `#[link(kind = "raw-dylib")]`，
需要 `dlltool` 生成导入库，而 `dlltool` 内部还要调汇编器 `as.exe`；本机当时只有 rustup 自带的
`dlltool.exe`，没有 `as.exe`（无 MSVC、无完整 mingw-w64 binutils）。

### 4.2 解除方式

安装 mingw-w64 binutils 到 `C://mingw64//bin`（GNU Binutils 2.47，含 `as.exe` / `dlltool.exe` / `ld.exe`）。

**注意**：该目录不在 cargo 的 PATH 里（Git Bash 的 `/mingw64/bin` 指向 Git 自带目录，没有 binutils），
必须显式前置：

```bash
export PATH="/c/mingw64/bin:$PATH"
export CARGO_BUILD_JOBS=1        # 本机并发编译会报 os error 5 文件锁
```

### 4.4 踩坑：Vite 构建被沙箱批量删除守卫拦截

`npm run build` 在清空 `ui/dist` 时被沙箱拦截：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":191,"targets":["ui\dist\pdfjs"]}
```

`ui/dist/pdfjs` 下有 191 个 cmap 文件，触发批量删除保护。处理：先把 `dist` 整体移走再构建
（`mv dist /tmp/dw-ui-dist-old`），vite 会新建目录，不再触发删除。**不要用 `rm -rf` 硬删**。
