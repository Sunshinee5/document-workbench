## 4. 功能完成

- `FontRegistry` / `FontDescriptor`：`FontRef` / `Family` / `Style` / `Encoding` / `Embedded` / `Subset` / cmap 七类信息。
- `FontEncoding`：`Identity` / `WinAnsi` / `MacRoman` / `Utf16Be` / `Other(String)`；`Other` → `EncodingUnsupported`。
- `normalize_unicode()`：确定性最小规范化；`FontDescriptor.cmap` 与查询键统一走该函数。
- Glyph Resolve：逐字符查 cmap，缺失即 `MissingGlyph`，**不静默替换**。
- Subset Planning：`ExtendSubset` / `ReuseEmbedded` / `NewSubset` 三策略 + `used_glyphs` 合并；不生成字体字节。
- `FontPatch` 四字段完整，可 JSON 往返。
- 五类中文错误 + 三类事件（Started / Finished / Failed，均带结构化载荷）。

## 7. 已知限制

1. **Unicode 规范化不是完整 NFKC**：只做 trim + 全角 ASCII 折半角 + U+3000 折空格（`13` C-5）。复杂组合字符、兼容字符分解等未覆盖。若后续需要完整 NFKC，须按 R1.1 引入规范化依赖或升 R2.0。
2. **不生成真实 Subset Font 字节**：本章只产计划（§九），Font Embed 属禁止项。18-08 负责把计划转成内容流变更。
3. **`FontRegistry` 不持久化**：不进 `DocumentSnapshot` / Save / Recovery（`13` C-8）。字体资源写盘归 18-08 + Save 链。
4. **`removed_fonts` 恒空**：`ReplaceText` 不删字体；字段留待 18-08 及后续章节使用（`13` C-7）。
5. **cmap 由调用方填充**：Parser 侧尚未把 PDF 字体资源丰富进 Registry；本章只提供数据结构与注册入口。
6. **构建环境**：本机 windows-gnu 缺 `as.exe`，TEMP 副本内仍用 `chrono 0.4.38` 规避 `raw-dylib`（仓库 `Cargo.lock` 未改，同 18-04 报告第 7 节第 1 条）。
