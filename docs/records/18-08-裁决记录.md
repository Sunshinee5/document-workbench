# 18-08《Content Stream Rewrite》架构裁决记录

日期：2026年11月25日
性质：过程记录，仅溯源；规范效力以 `docs/spec/14-Content-Stream-Rewrite-R1.md` 为准。

---

## 用户四项架构裁决

| # | 裁决 | 落地 |
|---|---|---|
| AD-21 | 唯一 Rewrite Engine | 采用；`dw-pdf::ContentRewriteEngine` 是唯一 Operator 重写入口，Save / Mapper / Editing 都不拼 Operator |
| AD-22 | Unknown 永久保留 | 采用；重写前后以 `unknown_signature()` 比对 Unknown 的名称、操作数与顺序，不一致报 `UnknownOperator` |
| AD-23 | Operator 顺序冻结 | 采用；只替换 `target_operator_index` 一处，其余原位克隆 |
| AD-24 | ContentPatch 为唯一输出 | 采用；引擎零 lopdf 写入、零 Save 调用 |

**编号一致性**：§三～§六 与 §十六 的 AD-21~24 完全一致，无编号冲突。

## 主理人冲突裁决

| # | 冲突 | 裁决 |
|---|---|---|
| C-1 | AD 编号一致 | 无冲突 |
| C-2 | **ContentPatch 形状冲突**：§六 `{ operators, streams }` vs §十 `{ page_id, stream_ref, operators }` | 统一 4 字段 `{ page_id, stream_ref, operators, streams }`。前两个供 Save 定位目标流；后两个是重写载荷。§十「禁止 Document / Selection / History」生效 |
| C-3 | Operator 类型放哪：`lopdf::content::Operation` 属 dw-pdf，ContentPatch 要 JSON 表达且被 Save 消费 | 在 **dw-core** 定义中性 `PdfOperand` / `PdfOperator` / `ContentPatch`；引擎在 **dw-pdf**，负责 lopdf ↔ 中性转换。依赖方向仍是 `dw-pdf → dw-core` |
| C-4 | §十 7「仅消费 EditingCommit + FontPatch」但 §五要校验「Stream 可解析」、§七要「Rebuild Stream」 | `RewriteRequest.source_stream` 是 **Parser 已解析出的原始字节**，属附带上下文而非重新解析字体；引擎只读源字节 |
| C-5 | AD-21 禁止 Mapper 拼 Operator，但 18-03 已实现 `ObjectMapper::to_content_stream()`（TJ/Do/re） | 保留该方法兼容 MT-04 Round Trip 既有测试，**明确不再作为 Save 的 Operator 来源**；AD-21 自本章生效，不追溯删除 18-03 已冻结 API |
| C-6 | CT-11「Save Integration」vs §一/§九禁止 Save / Incremental Save | CT-11 只验接口契约（字段齐全、可 JSON 往返、定位信息正确），**不实际写盘**；真写盘集成归 18-09 |
| C-7 | §十二 有 `UnknownOperator` 错误，但 AD-22 要求未知 Operator 不得报错 | `UnknownOperator` 表示**输出中的 Unknown 集合与输入不一致**（校验失败），不是"遇到未知 Operator" |
| C-8 | §六「禁止直接修改 lopdf」与 §一「Content Stream 生成」的边界 | 引擎只用 `Content::decode()` 解码源字节为内存 Operator；`encode_operators()` 仅用于 CT-04 RoundTrip 验证，不回写 lopdf 或 PDF |
| C-9 | `FontPatch.glyph_mapping: BTreeMap` 按 Unicode 排序，直接遍历会打乱原文字符顺序 | 按 `EditingCommit.object` 的 `unicode` 字符顺序逐字符查表；**不改 18-07 类型**；重复字符自然保留 |
| C-10 | Path 冻结接口 vs AD-22 Unknown 保留 | Path 是**已知**类型未实现（`PolicyNotImplemented`）；Unknown 是**未知** Operator 透传保留。互不冲突 |

## 补充裁决

- `ContentRewriteEngine` 无状态（`Copy`），不持有 EventBus（与 TaskManager 同规则，由调用方传入）。
- 文本重写**保留原 Operator 名**：源为 `Tj` 则输出 `Tj`（单字符串操作数），源为 `TJ` 则输出 `TJ`（数组包字符串），避免改变 Operator 种类。
- 字形字节按 **big-endian u16** 编码（Identity-H 风格）；超出 16 位的 glyph 报 `InvalidOperand`，不静默截断。
- 图片重写只替换 `Do` 的第一个资源名操作数，其它操作数与 Operator 名保持原样。
- 已知 Operator 集合仅用于 AD-22 校验的 Unknown 判定，**不用于过滤或排序**。

## 遗留边界（不在本章范围）

1. 不写 PDF、不做 Incremental Save；Save Pipeline 消费 `ContentPatch` 的实际写盘归 18-09。
2. 不重新解析字体、不生成字体字节（AD-24 / 18-07 C-2）。
3. `ObjectMapper::to_content_stream()` 保留但不再被 Save 用作 Operator 来源（C-5）；18-09 集成时需确认没有旁路调用。
