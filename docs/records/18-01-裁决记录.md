## 用户追加裁决（2026-11-24，第二轮）

用户认可前三条（spec 位置 / Driver 只是 Mapper / Selection 双轨），并新增三项冻结与一次路线调整：

| # | 冻结项 | 内容 |
|---|---|---|
| 11 | Object 生命周期 | `ObjectLifecycle { Created, Loaded, Modified, Deleted }`；Diff / Undo / Save 依据 Lifecycle，不用 Document Dirty，否则新增/删除对象无法表达 |
| 12 | Object Version | 每个 Object 带 `version: u64`，每次修改递增；AI / OCR / 协同 / Recovery 依据 Version，禁止重新 Hash |
| 13 | Object 永不直改 PDF | 正向 `lopdf → Parser → ObjectMapper → Object Tree`，反向 `Object Tree → ObjectMapper → lopdf`；全项目只有一个 Parser、一个 Mapper |

**Selection 进一步冻结为 Collection**：`pages: Vec<PageId>` + `objects: Vec<ObjectId>`，禁止 `current_page` / `current_object` 单值形态（AI/OCR/Annotation 需多选）。

**路线调整**：18-02 由 HitTest 改为 **PDF Object Parser**，Parser 与 Mapper 提前。正式路线：

```
18-01 Object Model → 18-02 Object Parser → 18-03 Object Mapper
→ 18-04 HitTest Engine → 18-05 Selection Engine
→ 18-06 Text Editing → 18-07 Font Rewrite → 18-08 Content Stream Rewrite
→ 18-09 Integration + QA
```

理由（用户原话意）：编辑、命中、选择都依赖对象，对象必须先从 PDF 稳定解析出来；Parser 先出，HitTest 直接吃 Parser 输出，不重复解析 PDF。
