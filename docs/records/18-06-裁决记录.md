# 18-06《Editing Engine》架构裁决记录

日期：2026年11月25日
性质：过程记录，仅溯源；规范效力以 `docs/spec/12-Editing-Engine-R1.md` 为准。

---

## 用户四项架构裁决（以 §十九 表述为准，见下方 C-1）

| # | 裁决 | 落地 |
|---|---|---|
| AD-13 | EditingSession 独立生命周期 | 采用；引擎持 `Option<EditingSession>`，Session 不新增字段，不进 Save / Recovery |
| AD-14 | WorkingCopy 为唯一可变对象 | 采用；编辑期间 `Page` 上的 `Object` 逐字节不变，`EditingState` 状态机是该裁决的生命周期表达 |
| AD-15 | Commit 为唯一写入口 | 采用；`version++` 与 `Lifecycle=Modified` 只在 Commit 调用 `Object::mark_modified()` |
| AD-16 | Selection 与 Editing 解耦 | 采用；Selection 变化只结束会话，Selection 不会自动进入编辑 |

## 主理人冲突裁决

| # | 冲突 | 裁决 |
|---|---|---|
| C-1 | **AD 编号重复**：§四～§七 把 AD-13/14/15/16 分别指派给 EditingSession / EditingState / WorkingCopy / Commit；§十九 又把同一批编号指派给 独立生命周期 / 唯一可变 / 唯一写入口 / 解耦 | 以 **§十九 四条为准**（用户明确「建议增加」）。§五 `EditingState` 作为 AD-14 的状态机表达并入，不单独占编号 |
| C-2 | §七 要求 Commit 走 `Mapper`，但 `ObjectMapper` 在 `dw-pdf`，`dw-core` **禁止依赖 `dw-pdf`**（依赖方向冻结 `dw-pdf → dw-core`） | Commit 产出 `EditingCommit { object, diff }`，**Mapper 步骤由上层在 dw-pdf 侧调用 `ObjectMapper::to_intermediate()`**。`dw-core` 内零 `ObjectMapper` 引用、零 Operator 拼接，同时守住 §二「不负责 Content Stream Rewrite」 |
| C-3 | §九 要求 Commit 前 `Capability Check`，但 `00` 冻结「Capability Gate 是**唯一**准入点，失败对外只抛 `TaskRejected`」 | Editing Engine **不在执行链上**（同 18-05 C-6）。它的检查是**编辑事务的本地前置校验**，错误码 `CapabilityDenied`，不替代、不绕过 `TaskRejected`；判据 `CapabilitySet::has(Capability::ObjectEditing)` |
| C-4 | §十三 / ET-07 要求对象级 Diff 可回放，但 `Diff::apply(&Document)` 只能改 `PageLayout`，`Object` 挂在 `Page` 上 | 新增 `Diff::apply_object(&mut Page)` / `Diff::revert_object(&mut Page)`；`Diff::apply(&Document)` 遇 `ObjectChange` 返回指向 `apply_object` 的明确错误，不静默成功 |
| C-5 | 18-01 冻结「`version` 每次修改递增」，回放 `before` 会把 version 退回去 | 单调性只约束**编辑动作**；回放必须与 Diff 完全对称，Undo 恢复 `before` 整份快照（含 `version`） |
| C-6 | §十四 只允许五类错误，「未在编辑中」「非法状态迁移」不属任何一类 | 归入 `ValidationFailed(中文原因)`，不新增第 6 类 |
| C-7 | §十二 说「返回 SelectionChanged」，但 Selection 事件由 Selection Engine 独占发布 | Editing 因选择变化结束时发 **`EditingCanceled { reason: SelectionChanged }`**，不重复发 `SelectionChanged`（避免双发） |
| C-8 | §五 状态链含 `BeginEdit` / `Commit` 两个状态，对外暴露瞬态无意义 | 二者单次调用内瞬态完成：`begin_edit()` 走 `Idle → BeginEdit → Editing`，`commit()` 走 `Editing → Commit → Idle`；`state()` 只可见 `Idle` / `Editing` |
| C-9 | §八 `ReplaceText` 与真实 PDF 文本替换（需字形/编码重写）的边界未写明 | 只改 `TextObject.unicode`，不碰 `glyphs` / `font` / 内容流。本章 Commit 后的对象在 Save 后**不会**直接改变 PDF 页面显示——18-06/18-07/18-08 的章节边界 |

## 补充裁决

- `EditingEngine` 不持有 `Page` / `SelectionState` / `EventBus`：`Page` 与 `SelectionState` 按引用传入，`EventBus` 由调用方传入（与 TaskManager 同规则）。
- `begin_edit` 失败必须回滚到 `Idle` 并清空 `session`，不留半开事务；`commit` 失败必须保留事务（用户可修正后重试）。
- Diff 的 `before` / `after` 存**整份 `Object` JSON**，而不是仅 payload，保证 `revert_object()` 能完整还原。

## 遗留边界（不在本章范围）

1. Font Rewrite 归 18-07，Content Stream Rewrite 归 18-08。本章 Commit 只改变对象模型，写盘效果要等这两章。
2. `EditingSession` 未进入 `Recovery`（AD-13 明确不持久化）；崩溃后编辑中的 WorkingCopy 丢失，符合「事务未提交即不生效」。
