## 一、总览

用户提交的《文档16》冻结了工作台形态（TitleBar → Ribbon → Workspace → Canvas → Inspector → StatusBar），
同时在 §十三 给出了技术栈**建议**。两者与项目现状的冲突共 11 项，逐条裁决如下。

其中 **C-1 是唯一影响技术路线的裁决**：拒绝 React 19 / Zustand / TanStack Query / shadcn/ui / Radix /
Lucide / cmdk / Motion / Resizable Panels / TanStack Virtual / Tailwind 的升版建议，

## 三、为什么拒绝技术栈升版（C-1 详述）

1. **规范层级**：`00` Architecture Freeze 是最高优先级，明确「改技术路线需 R2.0」。用户原文 §十三标题是「技术栈 **建议**」，
   而 Architecture Freeze 条款只冻结「布局 + 组件职责 + 禁止第二套 UI」，不含依赖清单。
2. **实现能力等价**：文档要的是「统一组件、统一主题、可拖拽、可虚拟化的长列表」。
   这些用 React 18 + CSS Variables 全部可实现，本次已实现并截图验证。
3. **风险**：React 19 会牵动 `@types/react`、Vite 插件、pdfjs 集成；Tailwind 会与「禁止硬编码颜色」的 Token 体系重复；
   shadcn/ui 依赖 Radix 的运行时行为（Portal / Focus Trap），会与「禁止弹窗、统一 Workspace」冲突。
4. **留口**：若后续确实要升版，须用户明确拍板 **R2.0**，届时重写本节并同步 `00`。

## 五、明确未做的部分（避免误读）

1. **对象级编辑 IPC**：18-05 ~ 18-08 的引擎只在 `dw-core` / `dw-pdf` 内闭环，没有 IPC 命令。
   本次**没有**新增编辑类 IPC，Edit Ribbon 的编辑类按钮为禁用态。
2. **对象级 Selection**：见 C-11，UI 侧只有只读 focus。
3. **OCR / 批注 / AI 的真实数据**：19 / 20 / 21 章未开始，相关 Workspace 只做入口与禁用态。
4. **内存占用**：状态栏「内存」项显示 `—`，前端拿不到进程内存，不臆造数字。
5. **对象树是文件投影**：投影自**源文件**，未保存的内存编辑不会出现在对象树里；保存成功后自动重新解析。

## 六、一句话结论

UI 结构按规范冻结落地，技术栈保持 React 18 + Vite 5 不变；17 / 18 章入口补齐且不越过已冻结的执行链；
19 / 20 / 21 / 22 的入口可见但禁用，符合「未实现显示禁用态、不得隐藏」的要求。
