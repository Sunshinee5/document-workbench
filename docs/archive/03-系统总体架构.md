# Document Workbench 开发文档 03

> **注意：本章部分条款已被 `00-A-架构决议.md` 修正，冲突时以决议为准。**
> 受影响条款：正式 MVVM 链路为 UI → ViewModel → Command → Service → Engine；Command 只转发不写业务；History 拆为 WorkspaceHistory 与 DocumentHistory、取消 HistoryService；Plugin 第一版即按契约（OCRPlugin → PluginManager → OCR Engine）实现；目录结构以本章为准。第五章已改为《Document Session 架构》。

## 系统总体架构（第一阶段）

Version：V1.0

### 一、整体设计思想

整个项目遵循一句话：所有文档能力都是"插件"，工作台才是主体。

不要：PDF 软件。而是：Document Workbench → PDF / Word / Excel / OCR / AI / Image。

PDF 只是其中一个能力。以后 Office、CAD、Markdown、图片都可以继续加。

### 二、架构原则

整个项目采用五层架构：

```
UI
↓
Workspace
↓
Service
↓
Engine
↓
Runtime
```

任何模块禁止跨层调用。

**第一层 UI**：负责窗口、菜单、Ribbon、右键、状态栏、Dock、标签、主题。

UI 绝不能解析 PDF、绝不能 OCR、绝不能转换 Word，只负责显示。

建议以后所有按钮全部调用 Command，例如"打开 PDF" → OpenCommand → Service。以后 Undo、Redo、AI 全部统一。

**第二层 Workspace**：这是整个项目的核心，不是 PDF。以后打开十个 PDF、Word、图片全部属于 Workspace。

```
Workspace
├── Document1
├── Document2
├── Document3
├── History
├── Selection
├── Clipboard
└── Plugin
```

所有 Document 统一。以后 AI 不用关心是不是 PDF。

### 三、Service 层

这一层网上几乎没人做，但是必须有。

例如：Open PDF → Workspace → DocumentService → PDFEngine。

为什么？以后 AI 也要打开 PDF，不用重新写。Service 统一。

- DocumentService
- ExportService
- OCRService
- OfficeService
- HistoryService
- PluginService
- ThemeService
- ConfigService

全部放这里。

### 四、Engine 层

这里禁止 UI。

- PDFEngine
- OfficeEngine
- ImageEngine
- OCREngine
- CompressEngine

以后所有第三方全部放这里。例如 PDF.js → PDFEngine，LibreOffice → OfficeEngine，OCRmyPDF → OCREngine。以后全部可替换。

### 五、Runtime 层（新增）

网上很多项目没有这一层，但以后 Agent 一定感谢。

```
Runtime
├── Fonts
├── Language
├── Plugin
├── Config
├── Temp
├── Cache
└── Logs
```

所有第三方运行时全部统一。以后升级不用改 Engine。

### 六、Document 对象（重点）

整个项目以后只有一个 Document。不要 PDFDocument、WordDocument、ImageDocument，统一 Document。

公共属性：id、path、title、type、engine、history、metadata、permission、thumbnail、modified、dirty。

PDF、Word、图片全部继承。例如：

```
Document
├── PDFDocument
└── WordDocument
```

以后 Agent 不用重复开发。

### 七、Command 系统

这里必须现在做，不要以后补。

所有按钮都是 Command，例如 DeletePageCommand、RotatePageCommand、OCRCommand、MergeCommand、ExportCommand。

以后 Undo、Redo、AI、宏、快捷键全部调用 Command。

### 八、History 系统

不要每个功能自己 Undo，统一 History → Command → Undo → Redo。

以后 AI 修改 100 页也可以 Undo。

### 九、Plugin 系统

第一阶段虽然不用，但是接口必须留。

```
Plugin
├── Load
├── Unload
├── Permission
├── Menu
└── Command
```

以后 OCR、AI、Office 全部插件。

### 十、Workspace 目录

```
Workspace/
├── current/
├── recent/
├── favorite/
├── temp/
├── cache/
├── autosave/
└── snapshot/
```

以后自动恢复全部在这里。

### 十一、整个目录

```
DocumentWorkbench
├── app
├── ui
├── workspace
├── service
├── engine
├── runtime
├── plugin
├── resource
├── lang
├── config
├── cache
├── log
└── DocumentWorkbench.exe
```

Agent 以后禁止乱放。

### 十二、为什么不用 MVC

很多 PDF 项目还是 MVC，建议不要。建议采用 MVVM + Command + Service + Engine。以后 AI、插件都会舒服很多。

### 十三、Agent 开发顺序

必须按照下面顺序，不要跳：

```
Runtime → Engine → Service → Workspace → UI → Plugin → AI
```

不要反，否则以后重构。

### 十四、本章验收标准

完成后 Agent 应该已经有整个框架。即使一个 PDF 都打不开也没关系，因为以后所有功能全部直接往里面放，不会重构。
