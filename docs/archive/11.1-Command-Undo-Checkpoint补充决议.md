# 11.1 Command / Undo / Checkpoint 补充决议

版本：1.1　｜　日期：2026年11月22日
定位：对《11-Command-Undo-Checkpoint架构（修正版V1.1）》的补充决议，闭合该版第六节列出的 Q1–Q7 七条残留缺口。与 11 章修正版同优先级，冲突时以本文件为准。

---

## 一、Document 内部可变性修正

### 原方案（废弃）

```
Document { inner: RefCell<DocumentInner> }
```

**废弃原因**：Tauri State 要求 `CoreState: Send + Sync + 'static`，而 `RefCell` 是 `!Sync`，导致 `CoreState` 无法进入 Tauri State，编译期直接失败（`E0277`，编译器提示改用 `RwLock`）。

### 新方案

使用 `std::sync::RwLock`：

```
Document {
    id,
    metadata,
    inner: RwLock<DocumentInner>,
}
```

**访问规则：**

- 读取：`document.read()` → 内部 `inner.read()`
- 修改：统一走 `document.mutate()` → 内部 `inner.write()`

**保持**：外部模块不能直接修改 `DocumentInner`。

最终链路：

```
Task → Document.mutate() → DocumentInner → Diff 生成 → History
```

---

## 二、ExecutionContext 的 Document 定义

**确认保持**：`document: &'a Document`

原因：`ExecutionContext` 不是 Document 管理器，它只代表一次 Task 执行环境。

流程：

```
Command → TaskManager → DocumentStore → 找到 Document
→ 创建 ExecutionContext → Task 执行
```

Context **不感知 DocumentStore**。8 字段冻结保持不变。

---

## 三、Diff 数据模型

恢复 `Command → Diff → Checkpoint` 链路。Diff 分两类。

### 1. Structure Diff

用于轻量结构变化：

- 页面顺序
- 页面旋转
- 删除页
- 添加注释
- 元数据变化

格式：JSON 可表达。例如：

```json
{ "type": "RotatePage", "page": 3, "oldRotation": 0, "newRotation": 90 }
```

### 2. Binary Diff

用于内容变化：

- 图片替换
- 内容流变化
- 大对象修改

保存：二进制块。

目录：

```
Recovery/
  session-id/
    ├── diffs/
    │     ├── diff001.bin
    │     └── diff002.bin
    └── checkpoints/
```

---

## 四、History 持久化

最终分两个级别。

### session.json — 保存 History 元数据

```json
{
  "history": {
    "cursor": 15,
    "entries": [
      { "id": "cmd001", "type": "DeletePage", "diff": "diff001" }
    ]
  }
}
```

保存内容：Command 类型、参数、cursor、Diff 引用。
**不保存大二进制。**

### Recovery 目录 — 保存实际恢复数据

包括 `diff` 与 `checkpoint`。

---

## 五、Checkpoint 定位再次确认

Checkpoint **不是** History，**不是** Command，**不是** Diff。

关系：

```
Command → Diff → History
每 N 条 → Checkpoint
```

恢复**必须**：

```
找到最近 Checkpoint → 加载状态 → 应用之后 Diff → 恢复当前状态
```

**禁止**直接重新执行 Command。

---

## 六、TaskBuilder 定义

确认：**不存在 TaskBuilder 类，不存在 TaskBuilder Manager。**

链路中的 `TaskBuilder` 表示「Command 生成 Task 的动作」，实现为 Command 的方法：

```rust
impl Command {
    fn build_tasks(&self, ctx: &ExecutionContext) -> Vec<Box<dyn Task>>;
}
```

因此**没有新增** Builder / Factory / Manager。

---

## 七、CommandRecord 定义

修正：`CommandRecord` **只是数据结构**，不是对象、不是服务。

**没有** `execute` / `publish` / `manage`。

结构：

```
CommandRecord {
    command_id,
    command_type,
    params,
    diff_reference,
    timestamp,
}
```

**事件发布**由持有 EventBus 的组件完成：

```
Task 完成 → History 写入 Record → CoreState/EventBus → 发布 HistoryChanged
```

**Command 不知道 EventBus 存在。**

---

## 八、跨文档 Command

确认：**不修改 ExecutionContext**。

例如 Merge PDF：

```
MergeCommand {
    inputs: Vec<PathBuf>,
    output: PathBuf,
}
```

执行时 Task 负责打开输入：

```
MergeCommand → MergeTask → Driver 打开 A/B → 生成 C
→ DocumentStore 注册 C → Workspace 新增 Tab
```

Context 仍然只服务当前执行目标。

---

## 九、最终 Command 链路（冻结）

```
Action
  ↓
Command
  ↓
Command::build_tasks()
  ↓
TaskManager
  ↓
ExecutionGraph
  ↓
Task
  ↓
Driver
  ↓
Document.mutate()
  ↓
Diff
  ↓
History
  ↓
Checkpoint
```

## 十、禁止事项更新

Agent 实现禁止：

1. **禁止** `RefCell<DocumentInner>`，**必须** `RwLock<DocumentInner>`
2. **禁止**新增 `CommandExecutor`
3. **禁止**新增 `HistoryManager` / `CheckpointManager` / `TaskBuilder`
4. **禁止** Task 直接修改 Document 字段，**必须**走 `Document.mutate()`
5. **禁止** Command 持有 TaskManager / EventBus

## 附：当前架构状态

11 章修正后，核心编辑闭环：

```
UI → Command → TaskManager → ExecutionGraph → Task → Driver
   → Document(RwLock) → Diff → History → Checkpoint
```

已满足：Rust 线程安全、Tauri State 要求、Undo/Redo 可实现、多文档可扩展、AI/插件可复用。

## 附二：实现层面的连锁影响（Agent 编码时必须注意）

以下是本次决议落地到 Rust 后必然产生的连带改动，不属于新增设计，仅为实现提醒：

1. **`RwLock` 不可 `Clone`** → `Document` 失去 `Clone`，进而 `DocumentStore`、`Session` 都不能再 `#[derive(Clone)]`。`SessionManager::create_session()` 改为返回所有权（move），不再 clone。
2. **`ExecutionContext` 仍可 `Clone`**（只持 `&Document` 引用，引用可 clone），不受影响。
3. **`Workspace` 由 `Vec<Document>` 改为 `Vec<Tab>`**，`Tab` 只存 `document_id`，因此 `Workspace` 仍可 `Clone`。
4. **`Session.history_index` 改为 `Session.history`**，会波及 `dw-core/src/lib.rs` 中的骨架测试构造代码。
5. **`dw-core/Cargo.toml` 需新增依赖**：`serde`（含 derive）、`serde_json`、`thiserror`。`uuid` 不强制引入 —— DocumentId / CommandId 建议用 `u64` 单调递增，避免额外依赖。
6. **`CoreState` 属于 `dw-desktop`，不属于 `dw-core`** —— 它是应用组装层（Composition Root），不是架构层，不得放进核心库。
